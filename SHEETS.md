# Обмен книги и телефона

Здесь написано, что именно скрипт читает, куда пишет и по какому правилу
решает споры. Это договор между книгой и приложением: пока он соблюдается,
обмен предсказуем.

## Три правила

**1. У каждой записи есть свой номер (ID).**
Он лежит в скрытом столбце **BH** того же листа и едет вместе со строкой.
Сортируй листы, вставляй строки в середину, двигай блоки — связь не
порвётся. Номер строки не значит ничего.

До этого запись узнавали по номеру строки. Любая вставка перемешивала
данные: правка по одному объекту уезжала в соседний.

**2. Поле правит тот, кто правил позже.**
У каждой записи одна метка времени. Книга ставит её, когда видит, что
строку меняли руками (сравнивает отпечаток значимых ячеек). Телефон — когда
человек сохранил карточку. Свежая версия побеждает целиком.

Метка из телефона, оказавшаяся в будущем, считается сегодняшней: убежавшие
часы не делают версию свежее. При равенстве побеждает книга — её правку
скрипт видит своими глазами.

**3. Удаление — это команда, а не поле.**

| Что сделал | Что происходит |
| --- | --- |
| Удалил запись в приложении | Строка в книге сереет, зачёркивается и получает дату в скрытом столбце **BI**. В приложении запись исчезает и больше не возвращается. |
| Удалил строку в книге | Запись исчезает в приложении. |
| Хочешь вернуть | Очисти столбец BI руками или заведи запись заново. |

Почему не «раз в книге есть, значит верни в телефон»: тогда удалить
что-либо с телефона стало бы невозможно в принципе — команда «удалить»
молча отменялась бы при каждом обмене. Именно это и происходило раньше.

## Служебные столбцы

| Столбец | Что в нём | Видно |
| --- | --- | --- |
| BH (60) | номер записи | скрыт |
| BI (61) | дата удаления из приложения | скрыт |

Стоят далеко за краем данных (самый широкий лист — «Договора», 46
столбцов) и намеренно не вставлены в начало: вставка столбца A сдвинула бы
все формулы и именованные диапазоны книги.

Скрытый лист `_ПОДРЯД` держит по строке на запись: номер, лист, метку
времени и отпечаток. Отпечаток — единственный способ понять, что строку
правили руками.

## Что читается и что пишется

Скрипт пишет **только** в перечисленные столбцы. Формульные — номер,
отдел, суммы, остатки, ранги, подписи карточек — не трогает никогда.
Ничего не очищается целиком: `clear()` в скрипте нет.

### Объекты (строка данных с 5-й)

| Столбец | Поле | Пишется |
| --- | --- | --- |
| A | № объекта | нет, формула |
| B | краткое наименование | да |
| C | полное наименование | да |
| D | заказчик | да, именем |
| E | адрес | да |
| F | тип здания | да |
| G | площадь | да |
| H | единица | да |
| I | примечание | да |

### Договора (с 5-й)

| Столбец | Поле | Пишется |
| --- | --- | --- |
| A | № договора | нет, формула |
| B | объект | да, именем |
| C | вид работ | да |
| D | исполнитель (юр. лицо) | да |
| E | статус | да |
| F | цена | да |
| G, H | начало, срок | да |
| I | отдел | нет, формула |
| J | ответственный | да |
| K, L, M | соисполнители | да |
| N, Q, T | условия оплат 1–3 | да |
| O, R, U | доли оплат 1–3 | да |
| P, S, V | даты поступления денег | **нет** |
| W | примечание | да |

Столбец «Оплачено» не пишется намеренно: в книге там дата поступления
денег, а в телефоне только галочка. Галочкой затирать дату нельзя.

### Сотрудники (с 5-й)

| Столбец | Поле | Пишется |
| --- | --- | --- |
| A | отдел | да |
| B | Ф. И. О. | да |
| C | должность | да |
| D | таб. № | да |
| E | трудоустройство | да |
| F | нахождение | да |
| G | ставка | **нет** |
| H | телефон / почта | да |
| I | комментарий | да |

Из столбца H телефоны и ники разбираются по виду: с собакой в начале —
телеграм, с точкой и собакой — почта, остальное с шестью цифрами и больше —
телефон. Обратно собираются через запятую.

### Сдача (с 5-й)

Пишутся: что сдаём (E), вид (F), план (G), факт (H), статус (I),
ответственный (J), примечание (K). Номер и подпись договора — формулы.

### Заказчики (с 4-й) — карточка, а не таблица

Лист собран блоками: столбец B держит наименование блока, C — подпись
реквизита, D — значение. Поэтому заказчик читается блоком строк, а каждый
реквизит ищется по своей подписи.

| Подпись в столбце C | Поле в приложении |
| --- | --- |
| Полное наименование | полное наименование |
| Юридический адрес | юридический адрес |
| ИНН, КПП, ОГРН | ИНН, КПП, ОГРН |
| Банк, Расчётный счёт, БИК | банк, счёт, БИК |
| Руководитель | руководитель |
| Телефон, E-mail | телефон, почта |

Значения пишутся обратно только в те строки, где такая подпись уже есть:
сочинять новые строки в вёрстке с объединёнными ячейками нельзя.

ОКВЭД, ОКПО, фактический адрес, адрес банка, корр. счёт и сайт в
приложении не хранятся — они читаются в книге и там же остаются.

## Что живёт только в телефоне

Готовность объекта и задачи по договору. В книге таких столбцов нет, и
заводить их незачем. При обмене они возвращаются телефону нетронутыми —
иначе первый же обмен стирал бы их вместе с приехавшей записью.

## Установка и проверка

1. Расширения → Apps Script, вставить `ПОДРЯД-ОБМЕН.gs` целиком.
2. Выполнить `НАСТРОИТЬ()` один раз. Заведёт скрытые столбцы, раздаст
   номера всем строкам и подхватит старые номера из прежнего служебного
   листа, чтобы записи не начали жизнь заново.
3. Развернуть → Веб-приложение → запуск от моего имени → доступ «у всех» →
   Развернуть. Ссылку `/exec` вставить в приложении: Настройки →
   Google-таблица.

`ПРОВЕРКА()` показывает, что скрипт видит в книге: сколько строк на каждом
листе, у скольких есть номер, сколько помечено удалёнными и как разобрался
первый заказчик.

После любой правки скрипта развёртывание нужно **обновить**, иначе телефон
продолжит говорить со старой версией.

## Проверка логики без книги

`tools/sync-test/test.js` гоняет обмен на подставной таблице: опознание
строк, удаление в обе стороны, повторные обмены, сортировка листа, переход
со старой версии. Запуск: `node test.js` из той же папки. Там же лежит
копия скрипта, которую тест читает.
